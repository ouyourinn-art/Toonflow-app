# 耀好原创工作室

原创工作室基于 Toonflow v2.0.8 改造，开发分支为 `yaohao`，`master` 保留用于跟随上游。原视频重绘程序继续在独立仓库维护。

## 当前功能

- 首页提供原创短剧、小说改编和继续项目三个入口。
- 新项目建立七个阶段画布，每个画布含可编辑的创作说明与正文节点。
- 工作区阶段导航直接打开对应画布；切换前保存当前正文及画布，失败时显示错误。
- 项目模式和创作需求保存在 `originalProject.json`，旧项目仍可通过原有画布入口打开。
- 没有选择语言模型时，纯文字需求保存为草稿。选定模型后，首页请求交给现有助手，先完善故事构思。
- 阶段说明和助手请求要求先确认完整剧本、统一角色 ID 与别名，再安排人物及场景资产；生图、生视频提示词保留在对应画布供编辑。
- Shugando 设置可填写 API 地址、Key、协议，获取或手动输入上游模型 ID，并保存到现有模型配置。助手与文本节点共用供应商列表。
- 移除首页官方探索、TF-Router 引导登录、官方充值和云插件市场入口，停用官方使用统计；新安装不再预装 TF-Router。
- 桌面应用标识和更新地址指向耀好 Fork。原作署名及 MIT LICENSE 保留。

阶段导航显示当前画布。一键制作完成的阶段显示勾选并打开该版生成画布；尚未生成的阶段仍打开原草稿。点击导航不会改变制作进度。

## 一键制作

工作区顶部提供「一键制作成片」，依次自动执行：完整剧本与导演分镜 → 人物和场景资产 → 引用资产生成分镜图 → 引用分镜图生成视频 → 按镜头顺序合成 MP4。内容强度跟随创作配置，不再对所有项目硬编码“非露骨表达”。

旁边的「只生成剧本与分镜 JSON」是独立的人工审核阶段：它只调用已选语言模型，生成完整剧本、唯一角色表、场景资产规划和结构化分镜，不初始化媒体供应商、不提交图片或视频任务，也不消耗媒体额度。短片输出 `originalRuns/<runId>/plan.json`；长片额外输出 `longBible.json` 和 `scenes/<sceneId>.json`。运行详情会列出这些文件并提供下载。

审核 JSON 后点击「审核 JSON 后生成资产与视频」，选择图片和视频模型再启动。服务端会把已完成规划复制到新的运行版本，复用原 `plan`、角色 ID、场景 ID 和分镜时间轴，不再次请求语言模型；短片/长片模式不能在这一步互换。只生成阶段的长片预算仅用于后续媒体制作，规划本身不会因为视频预算不足而被拦截。

「成人露骨 90 秒连续成片」预设使用 6 镜 × 15 秒、16:9、人物身份锁定、全片连续与自动合成；模型列表中存在 `seedance-2.0-white` 和 `gpt-image-2.5` 时自动选择。成人模式仅生成明确 25 岁以上的原创虚构成年人及清醒、自愿情节，并把无遮挡的成人构图要求加入实际剧本、生图和视频提示词。上游模型仍可能自行弱化或拒绝结果，预设不把提交成功等同于画面要求已满足。

「韩国成人露骨 10 分钟长片」是独立长片模式，默认 40 镜 × 15 秒、8 个场景、3 个原创虚构韩国成年角色、16:9、480p、Seedance 2.0、人物身份锁定、SFace 质检、每镜最多 2 次失败重试和 150 USD 视频预算上限。韩国设定只约束原创角色与现代韩国人物、环境细节，不仿照真实人物。

- 剧本模型从已配置语言供应商中选择，使用真实模型 ID；匹配到 5.6sol 时优先选中，不虚构别名，也不静默改用其他模型。
- 图片、视频分别选择实际媒体供应商。图片须同时声明文生图和多参考图能力，视频须支持图片参考，并声明合法的时长与分辨率组合。支持 15 秒时可选择 15 秒；不统一强制所有模型使用同一时长。
- 启动前检查供应商、Key、模型能力、画幅及合成工具。合成使用现有 FFmpeg；如缺少依赖，在提交生成前报错。
- 短片模式用一次语言请求产出完整剧本、唯一角色表与所有分镜。长片模式先建立全片圣经和唯一角色库，再按场景逐次展开剧本与分镜，最后合并并统一校验；不会要求语言模型一次返回 40–240 镜。两种模式都要求 `startState`、`endState` 和 `continuity`，并在提交生图前校验角色数、镜头数、别名、唯一 ID、资产引用和连续状态。
- 同一角色只生成一份资产；人物锁定模式要求角色资产保存固定年龄、脸型、五官、发型、肤色、体型、身体比例、痣或纹身等身份指纹，各镜头逐字复用。每镜仅引用实际出场的角色图与场景图，并在实际图片提示词中标注参考图顺序。
- 普通模式的视频引用对应分镜图。全片连续模式的第一镜引用第一张分镜图，第 2 镜起由本地 FFmpeg 抽取上一镜最后一帧作为实际首帧，并在任务详情显示该路径；这能加强人脸、姿势、空间和光线衔接，但一致性仍取决于所选生成模型，不代表经过逐帧视觉审片。
- 长片只在同一场景内传递上一镜尾帧；每个新场景重新使用角色资产和场景锚点校准，防止误差从第一镜累积到全片。每镜视频后每 0.5 秒抽帧，由 OpenCV YuNet 检脸、SFace 对照角色资产；检查角色覆盖率、陌生脸和单帧人物复制。未通过时只重做该镜，达到重试次数或预算上限即停止，不重做已通过的场景。
- 人脸质检模型首次使用时从 OpenCV Zoo 下载到本机数据目录并校验固定 SHA-256，不写入 Git。当前运行环境须提供 Python 3 与 OpenCV；启动长片前会检查依赖，避免先产生媒体费用再发现无法质检。SFace 默认同人余弦阈值为 `0.363`，可在长片设置中调整。
- 自动合成会把每段裁切或以最后一帧补齐到设定的单镜时长，再按镜头顺序拼接，并校验最终时长。6 镜 × 15 秒的输出目标为 90 秒。
- 面板展示步骤状态、完整实际提示词、参考任务与结果路径。阶段完成后发布画布，成片可通过「查看成片」打开原有视频节点播放或导出。
- 任务由服务器后台串行执行，每步完成保存。关闭面板或刷新页面不停止任务；请求暂停会在当前步骤完成后暂停。暂停或失败可继续未完成步骤，不自动重复已完成素材。
- 服务器重启后的未完成请求标为「服务中断」。恢复前须核对供应商任务记录，并确认可能的重复计费。当前没有上游任务 ID 的自动查单和结果认领能力，不能保证中断请求不会重复收费。一般失败也不无限自动重投付费任务。
- 新建一版保留旧版输出和原始草稿，不覆盖已有画布正文。续跑发现已完成文件丢失或为空时停止并报错，不静默重生。

最新状态保存到项目 `originalRun.json`。各版的 `plan.json`、语言请求/响应、Markdown 快照、媒体文件和阶段画布位于 `originalRuns/<runId>/`。可编辑文本节点正文沿用 `assets/<nodeId>/content.md`。手工修改画布不自动回写已排定任务；重做内容需新建一版。

一键制作接口：`POST /api/original/start`、`POST /api/original/status`、`POST /api/original/control`。接口沿用工作区边界校验；同一项目仅允许一条运行链，相同运行 ID 的启动重试不会新建任务。

## 使用

1. 在引导页或设置中的「Shugando 服务」填写连接信息，获取模型后选择需要使用的模型并保存。
2. 选择创作模式，填写需求，按需添加小说等附件，选择一个空文件夹作为项目目录。
3. 点击「一键制作成片」，填写或粘贴完整创作需求，选择语言、图片和视频模型，锁定角色数、镜头数、画幅及模型支持的时长与分辨率。短片可套用 90 秒预设；长片可套用 10 分钟预设，并核对场景数、重试次数、单段估价和总预算上限。
4. 若要先人工审稿，点击「只生成剧本与分镜 JSON」，查看或下载 JSON；确认角色、场景、分镜和时间轴后，再点击「审核 JSON 后生成资产与视频」。
5. 若不需要审核，直接点击「开始一键制作」。执行中可查看实际提示词与进度、请求暂停；发生错误后核对原因，再继续未完成步骤。
6. 已完成阶段通过顶部导航查看画布，合成完成后点击「查看成片」。也可以沿用原有画布与助手手工制作。

语言模型的 API 配置不会自动配置媒体供应商，也不会自动登录 Shugando 钱包。媒体模型继续通过原有媒体设置配置。内置 Shugando 媒体连接支持 `gpt-image-2.5` 和 `seedance-2.0-white`，可填写现有网关 Key。图片参考通过 multipart `/images/edits` 发送，最多四张；视频只接入单张首帧，支持 4–15 秒及横屏、竖屏、方形。图生视频还需配置当前品牌的参考图上传地址、用户名和有效令牌，不能使用其他品牌的默认地址；令牌到期后需更新。

短片视频只提交一次；长片视频只有在人脸质检失败时才按设置重试单个镜头。每次提交随后查询同一任务并带鉴权下载结果。成功结果保存上游任务编号，查询或下载失败时也在错误中保留编号；尚未实现重启后自动认领任务。上游对写实人物首帧的限制仍以实际响应为准。只有明确启动一键制作后才自动提交生成任务。

## 开发与构建

使用 Bun 1.4.3。首次准备桌面 SDK 后再执行类型检查：

```powershell
bun install --frozen-lockfile
bun apps/desktop/node_modules/electrobun/bin/electrobun.cjs prepare
bun run typecheck
bun run build
bun run build:nodes
```

开发启动：

```powershell
bun run dev
```

单独预览构建页面，可指定独立数据目录，避免改动现有配置：

```powershell
$env:TOONFLOW_SERVER_PORT = '3108'
$env:TOONFLOW_DATA_DIR = Join-Path (Get-Location) 'data/originalReadyData'
$env:NODE_ENV = 'production'
bun apps/server/src/index.ts
```

访问 `http://127.0.0.1:3108`。生产服务器预览使用数据目录下的 `workspaces`；桌面端和本机开发模式沿用原生目录选择。

`bun run build:desktop` 和 `bun run package:desktop` 为已有桌面构建入口。当前阶段尚未交付耀好独立 EXE 安装包；启动画面、安装器、协议隔离与发布产物需要在打包阶段统一完成。推送开发分支不等于发布安装包或部署到云服务器。
